# V1.9.4 ENTRY-PAIR

## 实时客户入库规则

只要群里最终形成 **客户图片 + 正式客户资料**，且图片检测不是撞客，就自动正式入库。

支持以下发送方式：

- 图片和客户资料在同一条消息/caption。
- 先发图片，之后同一员工补发客户资料。
- 先发客户资料，之后同一员工补发图片。
- 客户资料直接回复之前的图片，优先按 message_id 精确绑定。
- A 发图片、B 回复该图片补资料，也可以精确绑定入库。
- 图片直接回复之前的客户资料，也可以绑定入库。

分开发送时图片和资料默认保留 1 小时。多人同时发客户时，明确的 Telegram 回复关系优先，未回复时只自动匹配同一发送者最近的记录，降低串客风险。

图片单独发送仍然只是查询，不会立即正式入库；只要在缓冲期内补齐客户资料，就会转为正式客户。

# TG 防撞客机器人 V1.9.1 SAFE-MATCH SSCD-AI COPY-GUARD

GitHub + Railway 群聊专用版本。私聊关闭。

## 识别目标

**一张照片 = 一个客户。** 系统判断的是“是否为同一张照片的编辑/截图/裁剪/压缩版本”，不是判断两张不同照片里的人是否为同一个人。

支持的主要变化：原图重存、Telegram 压缩、缩放、裁剪、放大、黑白边、圆形头像、轻微旋转、左右镜像、亮度/滤镜变化、头像出现在资料页截图中、部分模糊等。

## V1.9 AI

V1.9 新增 SSCD Copy Detection AI 作为主同图 AI，原来的 MobileNet 只在 SSCD 不可用时作为备用。SSCD 候选与 pHash/局部特征候选取并集，再用 SIFT/AKAZE/RANSAC 等做配对验证。

首次部署会下载约 99MB 的 SSCD TorchScript 模型到 `/data/models`；Railway Volume 挂载 `/data` 后只需下载一次。

## 判定规则

- 完全同文件：100%
- >=90% 且有强同图证据：自动撞客
- 84%~89.99%：疑似撞客，人工确认/误判
- 明显不同：新客户

低信息图片会采用更保守的自动判定，避免不同纯色/简单默认头像因 pHash 相同而误撞。

## Railway 必须设置

Variables：

```text
BOT_TOKEN=你的机器人Token
DATA_DIR=/data
```

给 worker 挂载 Railway Volume：

```text
/data
```

V1.9 默认在 Railway 上强制检查 Volume。没有 Volume 时会拒绝启动，不会静默使用临时空数据库。

## AI 索引

升级后旧客户图片会在后台逐批生成 SSCD 描述符。群里发送：

```text
/aistatus
```

可以查看 AI 模型和历史图库索引进度。

## 隐私模式

BotFather -> `/setprivacy` -> 选择机器人 -> `Disable`，并建议把机器人设为正式群管理员。


## V1.9.2 MATCH-PREVIEW

- 撞客或疑似撞客时，机器人会把算法真正命中的历史图片直接回复到本次提交图片下面。
- 审核人员可直接上下对比“本次提交图”和“历史命中图”。
- 疑似撞客的【确认撞客 / 误判】按钮直接显示在历史命中图消息上。
- 如果历史图片文件不可读取，会保留文字结果并提示，不影响检测。
- 可通过 Railway 变量 `SHOW_MATCHED_IMAGE=0` 关闭历史图片展示；默认开启。


## V1.9.4 图片备注入库
Telegram 图片 caption/备注中包含正式客户资料时，图片与资料视为同一条正式客户记录并自动入库。支持多行和单行多字段。
